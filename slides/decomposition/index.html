Time series decomposition

A decomposition model decomposes a time series into multiple components.

Usual components include:

trend (\(T\)), seasonality (\(S\)), remainder (\(R\))

Why decompose data?

  • Explore constituent patterns in a time series
  • Seasonal adjustment for long-term decision making
  • Simplifies modelling of complex patterns

Decomposition structure

Decomposition models are usually either

  • Additive: \(Y = T + S + R\)

  • Multiplicative: \(Y = T \times S \times R\)

💡 The sum of its parts

We can forecast each component independently, then combine to forecast the original series.

Probablistic forecasts are convolutions of additive parts.

\[y_{T+h|T} = T_{T+h|T} + S_{T+h|T} + R_{T+h|T}\]

Decomposition models

  • Classical decomposition
  • STL decomposition
  • X11 decomposition
  • SEATS decomposition
  • STR decomposition
  • … and more.

Additive decomposition via STL

\[ y_t = S_t + T_t + R_t \]

  • \(y_t=\) data at time \(t\)
  • \(T_t=\) trend-cycle component at time \(t\)
  • \(S_t=\) seasonal component at time \(t\)
  • \(R_t=\) remainder component at time \(t\)

(M)STL Decomposition

Advantages

  • Handles any seasonality of any periodicity.
  • Allows seasonality and trend to change over time.
  • Change sensitivity can be tuned via window sizes.
  • Optionally robust to outliers.

Disadvantages

  • Additive decomposition only.
  • Simplistic model (no trading day or holiday effects).

Decomposing multiplicative data

STL can’t decompose multiplicative patterns.

This isn’t a problem though, since we
have a transformational trick 🪄

\[\begin{aligned} \log(Y) &= \log(T \times S \times R) \\ &= \log(T) + \log(S) + \log(R) \end{aligned}\]

We must transform multiplicative patterns to additive patterns before STL decomposition.

Decomposition forecasting

Forecast components with simple models, then combine the component forecasts.

Seasonal adjustment

We usually model/forecast trend (\(T\)) and remainder (\(R\)) together using a single model - this is known seasonally adjusted.

\[ y_{T+h|T} = (T+R)_{T+h|T} + S_{T+h|T} \]

Decomposition forecasting

These forecasts are normally distributed:

\[S_{T+h|T} \sim N(\mu_{S,T+h}, \sigma_{S,T+h}^2)\]

\[(T+R)_{T+h|T} \sim N(\mu_{T+R,T+h}, \sigma_{T+R,T+h}^2)\]

The combined forecast is a convolution.

\[Y_{T+h|T} = S_{T+h|T} + (T+R)_{T+h|T}\]

If the forecasts are independent: \[Y_{T+h|T} \sim N(\mu_{T+R,T+h} + \mu_{S,T+h},\ \sigma_{T+R,T+h}^2 + \sigma_{S,T+h}^2)\]

If they’re not independent:

\[E(Y_{T+h|T}) = \mu_{T+R,T+h} + \mu_{S,T+h}\]

\[\text{Var}(Y_{T+h|T}) = \sigma_{T+R,T+h}^2 + \sigma_{S,T+h}^2 + 2\sigma_{T+R,S,T+h}\]

Convolutions of forecasts

The PDF of \(Z = X + Y\) is a convolution of:

🎲 Independent variables

Marginal densities are sufficient:

\[f_Z(z) = (f_X * f_Y)(z) = \int_{-\infty}^{\infty} f_X(x)\, f_Y(z - x)\, dx\]

🔗 Dependent variables

The joint density is required:

\[f_Z(z) = f_{X,Y}(z) = \int_{-\infty}^{\infty} f_{X,Y}(x,\, z - x)\, dx\]

(it’s technically not a convolution now, many terms exist)

Convolutions of forecasts

When a single seasonal window is used, \(S_{T+h|T}\) and \((T+R)_{T+h|T}\) are independent.

Since window = Inf, the seasonality is constant and seasonal naive exactly predicts the seasonal component (0 variance).

We can convolve these distributions together:

retail_fc_ets$value[2]

Convolutions of forecasts

In fable, combinations of Gaussian forecasts use correlations between components.

🔢 Covariance structure

\(\Sigma_h = D_hR_1D_h\)

Where

  • \(R_1\) is the 1-step error correlation matrix, and
  • \(D_h\) is a diagonal matrix of forecast standard deviations.

🔔 Gaussian copulas

This is closely related to Gaussian copulas.

The correlation matrix is estimated from the joint response residuals of component models.

Back-transforming forecasts

Lastly, we must undo the transformation to produce forecasts on the original scale.

🔄 Transforming distributions

If \(X \sim F\) and \(X = g(Y)\), then the PDF of \(Y\) is:

\[f_Y(y) = f_X(g^{-1}(y)) \left| \frac{d}{dy} g^{-1}(y) \right|\]

📐 Example: back-transforming \(log(Y) \sim N(\mu, \sigma^2)\)

If \(X \sim N(\mu, \sigma^2)\) and \(X = \log(Y)\), then \(g^{-1}(y) = e^y\) and \(\frac{d}{dy}e^y = e^y\),

\[f_Y(y) = f_X(e^y) \cdot e^y = \frac{1}{y\sigma\sqrt{2\pi}} \exp\!\left(-\frac{(\log y - \mu)^2}{2\sigma^2}\right)\]

i.e. \(Y \sim \text{LogNormal}(\mu, \sigma^2)\).

Back-transforming forecasts

⚖️ “Bias adjustment”

Quantiles (incl. medians) can be directly back-transformed:

\[Q_p(Y) = g^{-1}(Q_p(X))\]

However, the mean does not back-transform directly:

\[E(Y) = E[g^{-1}(X)] \neq g^{-1}(E[X])\]

For \(X \sim N(\mu, \sigma^2)\), a 2nd-order Taylor expansion gives:

\[E[g^{-1}(X)] \approx g^{-1}(\mu) + \frac{1}{2}\sigma^2 \cdot (g^{-1})''(\mu)\]

For \(g^{-1}(x) = e^x\), this is exact: \(E(Y) = e^{\mu + \sigma^2/2}\)

Larger \(\sigma^2\) \(\Rightarrow\) bigger correction.

Decomposition forecasting

Decomposition forecasts are specified with:

decomposition_model(
  dcmp = `decomposition`,
  ... # (models for each component)
)

🔧 decomposition_model() handles everything

  • decomposition of the original series,
  • forecasting each decomposed component,
  • convolution to combine forecasts with covariance,
  • back-transformation of forecasts to original scale.

The Australian retail forecasts were:

decomposition_model(
  dcmp = STL(box_cox(Turnover, lambda = 0.2) ~ season(window = Inf)),
  ETS(season_adjust),
  SNAIVE(season_year)
)
